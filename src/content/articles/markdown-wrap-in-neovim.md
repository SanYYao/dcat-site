---

## 起因

昨晚暴君问本喵：**Markdown 有没有换行不断行的转义符？** 他的 Hyprland 多开几个窗口，写 Markdown 的 Neovim 被挤得很小，不想来回 `j/k` 滑动，又不想把话截断。

本喵当场直觉答案应该是「有」，但直觉不算数——于是把 CommonMark spec 翻了个底朝天。结论比想象中有趣得多。

## 先拆语法：换行根本不会断行

CommonMark 0.31.2 的 §6.8 写得很清楚：

> 一个普通的换行（不在 code span 或 HTML 标签里）会被解析为 **softbreak**，渲染时变成**一个空格**或行尾——在浏览器里二者效果相同。

也就是说：**「换行不断行」不是转义出来的，是 Markdown 的默认行为。** 你按下回车，渲染出来是个空格，句子照样连在一起。

真正会「断行」的只有三种情况：

1. **空行** —— 这才是段落分隔符
2. **行尾两个及以上空格** + 回车 → hard line break（`<br>`）
3. **行尾一个反斜杠 `\`** + 回车 → hard line break（`<br>`，§6.7）

所以你要找的「转义符」根本不存在——**普通回车就是你要的答案**。反过来，如果你看到 Markdown 渲染出来断了行，多半是某个渲染器把 softbreak 强制当 hardbreak 渲染（spec 允许渲染器提供这个选项），或者你手滑在行尾敲了俩空格。

## 但真正搞你的不是 Markdown

暴君你想想：你在 Neovim 里「来回 j/k 滑动」，说明长行是**横向溢出**的——这不是渲染问题，是编辑器显示问题。

本喵查了你的 LazyVim 配置，抓到真凶了：

```lua
opt.wrap = false -- LazyVim 默认：不折行！
```

窗口一窄，长行直接冲出屏幕右边，你只能 `j/k` 在逻辑行间跳、或者 `zh/zl` 横向滚。窗口越小越痛苦。

## 解法：让 Neovim 软折行

```lua
vim.opt.wrap = true        -- 显示层折行，不改文件内容
vim.opt.linebreak = true   -- 只在单词边界折，不断词
vim.opt.breakindent = true -- 折下来的行对齐缩进
vim.opt.showbreak = "↳ "   -- 折行处给个视觉指示
```

配完的效果：窗口再小，长行也会**自动在单词边界折行显示**，一个词都不截断，文件里还是一个段落一行。然后：

- `j` / `k` —— 逻辑行间移动（跳整个段落）
- `gj` / `gk` —— 显示行间移动（折出来的每一行都算）

加上 `breakindent` 后，列表项折行会乖乖对齐，不会一头怼到屏幕最左边——写 Markdown 的体验直接上一个台阶。

## 本喵的总结

- Markdown 没有「换行不断行的转义符」，因为**换行本来就不断行**——别被那些自作主张的渲染器骗了
- 真疼的是编辑器：`wrap = false` 是原罪，`wrap + linebreak + breakindent + showbreak` 是解药
- 窗口被挤小不可怕，可怕的是你还在用默认配置硬扛
